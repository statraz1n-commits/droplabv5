# DROPLAB 6.0 — бесплатный CS2 case simulator

DROPLAB — **виртуальный** многопользовательский симулятор открытия кейсов с сервером Node.js 22.13+, SQLite, авторизацией Steam OpenID, регистрацией по email/нику, гостевым входом, инвентарём, апгрейдером, монетами, контрактами, поддержкой и админ-панелью. **Никаких настоящих денег, депозитов, торгов и выводов CS2-скинов.** Независимый фанатский проект, не связан с Valve/Steam или CaseBattle.

## Запуск

Установи Node.js **22.13+**, распакуй ZIP и открой терминал в папке, где расположен `package.json`.

```bash
npm install
npm start
```

Открой **http://localhost:3000**. Все зависимости встроены в Node.js, установка сторонних npm-пакетов не нужна. Чтобы проверить код и API:

```bash
npm run check
npm test
```

В архиве **нет** действующих баз данных, реальных паролей и `.env`. Новая база создаётся при запуске по пути `./data/droplab.sqlite` (если не задан `DB_PATH`).

## Администрация

Начальный локальный доступ: **xtc / Skeleton**. Войти: аватар аккаунта → Вход → Вход для администратора. Учётная запись создаётся на сервере автоматически. Пароль хранится в SQLite как хеш scrypt, а не в исходном виде.

**Важно:** этот пароль широко известен — **замени его до публикации сайта**. Для Render в разделе Environment задай `ADMIN_USERNAME=xtc` и **другой, сильный и уникальный** `ADMIN_PASSWORD`. Не коммить `.env` в репозиторий. При изменении `ADMIN_PASSWORD` сервер обновляет пароль администратора после перезапуска.

В админке есть три раздела: «Игроки», «Поддержка» и «Журнал действий». Поиск работает по нику, внутреннему ID, SteamID и публичному коду `DL-XXXXXXXXXX`. После выбора игрока доступны:

- просмотр профиля и активного инвентаря;
- добавление и установка виртуального баланса CR/монет;
- удаление конкретного скина (с записью в журнал);
- бессрочный или временный бан, таймаут в минутах, снятие ограничений;
- специальные **публично отмечаемые** игровые режимы для будущих попыток: обычный, гарантированно минимальный или максимальный *дроп из набора данного кейса*; для апгрейда — стандартная формула (`-1`) или фиксированный шанс от 0 до 100%.

Специальные режимы **видны владельцу аккаунта в профиле и меню**. Условия модифицируются только **до** следующего игрового действия: нельзя поменять уже выданный результат. «Минимальный дроп» не означает «ничего не выдаётся» — каждый оплаченный виртуальными CR кейс по-прежнему выдаёт предмет. Заявленных как обычные шансов сервер не скрывает.

Если игрок заблокирован/получил таймаут, игровые операции будут отклонены сервером; обращения в поддержку остаются доступны для обжалования. Администратор не может заблокировать самого администратора. Журнал сохраняет действия модерации и удаления.

## Что входит в 6.0

- **120 кейсов и 304 виртуальных предмета** — бюджетные, мемные/brainrot, оружейные (AK, AWP, M4, MP9), монетные и сверхдорогие коллекционные. К каждому кейсу сервер определяет набор и вероятности. Все цены в CR **условные, не рыночные**; названия скинов основаны на существующих предметах CS2 и известных редких паттернах. Комбинация названия и условной цены не подтверждает существование конкретного частного предмета в Steam.
- **SABYA 12** и **MUKHA CASE** — две авторские обложки, созданные на основе присланных фотографий. Изображения находятся в `public/assets/covers/`.
- **32 лимитированных кейса** отдельным блоком в начале главной и каталога, среди них SABYA 12 и MUKHA CASE. Таймер составляет **7 дней после первого запуска версии 6 на конкретной базе**. Момент старта хранится в `site_settings` SQLite и не сбрасывается после перезапуска. По истечении срока кейсы исчезнут из витрины и станут недоступны для открытия. Для сохранения таймера нужна постоянная база.
- **Сортировка** сначала дешёвые/дорогие, отдельные разделы лимитированных и обычных кейсов, фильтры по типу, случайный доступный кейс.
- **До 9 кейсов за один запрос** — каждая рулетка крутится отдельно; баланс списывается, а скины выдаются **сразу на сервере до окончания анимаций**. Можно немедленно перейти к инвентарю/апгрейдеру.
- **Апгрейдер** с выбором до 6 предметов, добавлением CR, обычной и длинной плавной анимацией, фаст-режимом без ожидания, звуками и кнопкой «Новая попытка». Использованные скины расходуются одной транзакцией и исчезают из инвентаря при ответе сервера.
- **Профиль и инвентарь**: лучшие/общие дропы, сумма полученного, рейтинг по CR, любимый кейс по количеству открытий, статистика апгрейдов, монеты и промокоды. Есть открытые публичные профили с аватаром/именем, инвентарём и статистикой. Email и хеши паролей публично не передаются. Поиск игроков доступен в «Топ игроков»; имена в ленте ведут в профиль.
- **Только реальные серверные выпадения** в ленте — нет ботов, фиктивных событий или остановки анимации при наведении; лента проверяется на обновления раз в 10 секунд.
- **Поддержка**: обращения создаются в пользовательском аккаунте и сразу доступны в админ-панели; можно отвечать и закрывать. После закрытия ни игрок, ни администратор **не могут больше отвечать** или повторно открыть этот тикет; для нового вопроса создаётся новый.
- **Логин**: Steam OpenID, email + ник + пароль, гостевой режим. На один хеш IP допускается один **новый** гостевой стартовый баланс, существующий гость восстанавливается защищённой cookie. Общие внешние IP (например, общественный Wi-Fi, CGNAT) ограничивают нескольких людей одновременно; при необходимости используй обычную регистрацию.
- **Футер**: ссылка на правила/условия, поддержку и [Instagram juliasss_s](https://instagram.com/juliasss_s). Кнопки используют преимущественно монохромные символы вместо разноцветных emoji. Увеличены размеры текстов, использован более мягкий шрифт Nunito Sans.

## Steam OpenID, имя и аватар

При успешной авторизации через официальный Steam OpenID сайт использует **проверенный SteamID**. Чтобы получить **Steam ник и аватар** из Web API, задай `STEAM_WEB_API_KEY` в приватных переменных окружения. Без ключа вход Steam работает, но отображается резервное имя `Steam #XXXXXX` и стандартный аватар. Имя/аватар/SteamID сохраняются в SQLite и обновляются при повторной авторизации. **Сайт никогда не запрашивает Steam-пароль.**

Публичный адрес Steam OpenID должен совпадать с `BASE_URL` и использовать HTTPS (например `https://example.onrender.com`).

## Настройки окружения

Смотри `.env.example`. Ключевые переменные:

```dotenv
PORT=3000
BASE_URL=http://localhost:3000
DB_PATH=./data/droplab.sqlite
SESSION_SECRET=ТВОЯ_ДЛИННАЯ_СЛУЧАЙНАЯ_СТРОКА_ОТ_32_СИМВОЛОВ
ADMIN_USERNAME=xtc
ADMIN_PASSWORD=ПРИДУМАЙ_СВОЙ_СИЛЬНЫЙ_ПАРОЛЬ
ADMIN_STEAM_IDS=
STEAM_WEB_API_KEY=
```

Для локальной проверки можно не задавать `ADMIN_PASSWORD`, тогда используется `Skeleton`. **Не оставляй этот пароль на публичном сервере.**

## Размещение на Render

1. Загрузи папку проекта в GitHub, **не добавляя `.env`, SQLite и приватные секреты**.
2. Render → New → Web Service → подключи репозиторий. Node.js 22.13+, Build Command `npm install`, Start Command `npm start`.
3. Render → Environment: запиши реальный `BASE_URL`, длинный `SESSION_SECRET`, `ADMIN_USERNAME=xtc`, новый `ADMIN_PASSWORD`, а для аватаров Steam — `STEAM_WEB_API_KEY`.
4. Для постоянного SQLite-хранилища нужен persistent disk с `DB_PATH=/var/data/droplab.sqlite` (пример в `render.yaml`, тариф с диском). **На бесплатном Render локальные файлы SQLite могут пропасть после перезапуска/деплоя** — с ними пропадут и балансы, и таймер лимитированных кейсов. Для бесплатного постоянного хранения понадобится отдельно реализовать внешнюю базу (в этом архиве не реализована).

Просто загрузить ZIP на Netlify недостаточно: проект содержит сервер и базу данных.

## Обновление с DROPLAB 5.0

1. **Останови старый сервер**. Сделай копию базы `droplab.sqlite` вместе с файлами `-wal` и `-shm` (либо согласованный бэкап через SQLite API).
2. Замени файлы кода и статические ресурсы, но **не заменяй существующий файл базы**.
3. Убедись, что `DB_PATH` указывает на прежнюю базу и установлены необходимые приватные переменные окружения.
4. Запусти `npm install && npm start`. При старте сервер добавит новые поля и таблицы (`site_settings`, `moderation_logs`, поля ограничения и специальных режимов). Профили, балансы, монеты, инвентарь и история должны сохраниться.

## Важно перед публикацией

Сервис создаётся как **прототип фанатского симулятора**. Перед широким открытием необходимо протестировать защиту от злоупотреблений, продумать подтверждение email и восстановление пароля (они **не реализованы**), настроить резервные копии, политику конфиденциальности и юридически корректные условия использования с учётом страны запуска. Изображения настоящих CS2-скинов могут подгружаться из общедоступного каталога; если он недоступен, используется локальный силуэт предмета.

Автоматические тесты: `npm test`. Браузерные проверки выполнены с локально подставленными ответами API (полноценный сетевой браузерный тест окружение не позволило), а серверные запросы с реальной временной SQLite-базой проверены отдельно.
