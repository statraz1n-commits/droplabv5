# DROPLAB 5.0 — CS2 case opening simulator

DROPLAB — многопользовательский **симулятор** открытия CS2-кейсов с сервером на Node.js 22.13+, SQLite, авторизацией Steam OpenID, логином по email, гостевым входом, апгрейдами, контрактами, виртуальными CR и монетами ✦. Все предметы и цены виртуальные; пополнений реальными деньгами, торговли и вывода в Steam **нет**. Не является официальным продуктом Valve/Steam или CaseBattle.

## Старт за 2 команды

Установи Node.js версии **22.13+**, распакуй архив, открой терминал там, где находится `package.json`:

```bash
npm install
npm start
```

Затем открой **http://localhost:3000**. Никакие внешние npm-пакеты не требуются. Для проверки: `npm run check && npm test`.

## Готовый администратор

**Начальные учётные данные для первого локального запуска:**

- Логин: **xtc**
- Пароль: **Skeleton**

Открой «Войти» → «Вход для администратора». Администратор создаётся автоматически при старте сервера, пароль хранится в базе в виде защищённого хеша scrypt, а не исходного текста. Профиль `xtc` не создаёт новых бесплатных гостевых профилей.

**ОБЯЗАТЕЛЬНО СМЕНИ ПАРОЛЬ ПЕРЕД ПУБЛИКАЦИЕЙ.** Стартовый пароль известен из этой инструкции и не подходит для сайта, доступного в интернете. Для публичного Render установи `ADMIN_USERNAME=xtc` и **свой длинный уникальный** `ADMIN_PASSWORD` в приватной панели Render → Environment. После рестарта сервер обновит пароль админа из переменной окружения. Не записывай секреты в GitHub. На локальном компьютере можно создать `.env` по образцу `.env.example`.

Админ-панель позволяет искать игроков по нику, SteamID, внутреннему или публичному ID (`DL-XXXXXXXXXX`), выдавать/изменять CR и ✦, читать тикеты, отвечать в поддержку и настраивать **отображаемые игроку** коэффициенты шансов от 50 до 150%. Список начислений и изменений сохраняется в базе. Нельзя изменить результат уже завершённой попытки.

## Функции 5.0

- **83 кейса**: дешёвые, дорогие, мемные, тематические, сезонные, за монеты, оружейные (AWP, AK-47, M4, MP9 и другие), коллекционные. Некоторые сезонные кейсы имеют дату закрытия; неактивные кейсы недоступны для покупки. Обложки входят в архив.
- **288 виртуальных скинов** по мотивам существующих предметов и коллекционных комбинаций CS2; изображения реальных скинов пытаемся получить из внешнего общедоступного каталога. Если сеть/картинка недоступна, отображается локальный силуэт. **Оценки CR игровые, не цены реального рынка.**
- **Открытие до 9 кейсов за раз**: количество ×1 / ×2 / ×3 / ×5 / ×7 / ×9 или МАКС по балансу. Результат, списание и выдача всего лута проходят **атомарно на сервере до анимации**; можно перейти на страницу апгрейда сразу после нажатия и увидеть скины.
- **Апгрейдер:** до 6 исходных скинов, доплата CR, любой более дорогой предмет (включая очень дорогие), быстрые проценты/множители, фильтр по цене, сдвинутая вниз зона победы. Плавное вращение ~6 сек или длинное ~9,5 сек; есть **ФАСТ**, мгновенный результат, «Новая попытка», звуки. Результат всегда заранее выбирает сервер независимо от анимации.
- **Профиль** с уникальным публичным ID, лучшим дропом, общим объёмом полученного лута, статистикой открытий, инвентаря, апгрейдов, контрактов и любимым кейсом (по максимальному числу открытий); небольшое выпадающее меню аккаунта в верхней панели.
- **Поддержка:** создание тикетов, переписка с администратором, смена статуса обращения. Сведения сохраняются в SQLite.
- **Гостевой вход один раз на IP:** сервер хранит хеш IP, не сам адрес; сохранённая защищённая cookie позволяет вернуться в тот же гостевой аккаунт после выхода. Если удалить cookie, старый гость на том же IP **не восстановится**: лучше зарегистрировать email/пароль до удаления данных браузера. При общем внешнем IP (например, Wi-Fi, кампус, CGNAT) ограничение может затронуть нескольких разных людей; используйте регистрацию.
- **Email + ник + пароль:** отдельная регистрация и вход (пароли хешируются через scrypt). **Подтверждение владения email и восстановление пароля по почте не реализованы** — это нужно добавить, если сайт будет публичным.
- **Промокоды**: иногда выдаются при открытии кейса, бонус небольшой (+15–60 виртуальных CR), код одноразовый, привязан к владельцу и действует ограниченный срок; вводится в профиле.
- **Персональные коэффициенты** шансов видны игроку и учитываются в опубликованном составе кейса и вычислении процента апгрейда. Скрытого ухудшения шансов после крупной победы или тайного «открута» нет.
- **Монеты ✦:** начисляются за открытия и успешные апгрейды; тратятся только на специальные кейсы, выдающие виртуальные предметы. Плюс бесплатное пополнение CR с периодом ожидания, дневной бонус и продажа предметов за CR.

## Экономика и честность

- Стоимость кейса и минимальная стоимость предмета, математическое ожидание и вероятности открыто показываются игроку. У дорогих CR-кейсов задан ценовой нижний порог дропа; у дешёвых риск выше. Суммарное математическое ожидание CR-кейсов ниже цены открытия — это **виртуальная** экономика.
- Реальная вероятность не подменяется анимацией. Сервер выбирает исход с использованием криптографического генератора. В интерфейсе показаны персональные коэффициенты, если администратор их изменял.
- Картинки, игровые цены и названия не подтверждают наличие соответствующего реального оружия или предмета в вашем Steam-инвентаре.

## Переменные окружения

Смотри `.env.example`. Основные:

```dotenv
PORT=3000
BASE_URL=http://localhost:3000
DB_PATH=./data/droplab.sqlite
SESSION_SECRET=ЗАМЕНИ_НА_СЛУЧАЙНУЮ_СТРОКУ_32_СИМВОЛА_И_ДЛИННЕЕ
ADMIN_USERNAME=xtc
ADMIN_PASSWORD=ЗАДАЙ_ДРУГОЙ_ДЛИННЫЙ_ПАРОЛЬ_ПЕРЕД_ПУБЛИКАЦИЕЙ
ADMIN_STEAM_IDS=
STEAM_WEB_API_KEY=
```

`ADMIN_PASSWORD` в `.env` **заменяет** стартовый `Skeleton`; если хочешь сначала проверить локально именно стандартный пароль, не задавай эту переменную. Не загружай `.env` в GitHub. `STEAM_WEB_API_KEY` необязателен; Steam OpenID требует корректный публичный HTTPS `BASE_URL`.

## Render

1. Загрузить файлы в приватный или публичный GitHub-репозиторий **без `.env` и SQLite**.
2. Создать Render Web Service, выбрать Node 22.13+; **Build Command**: `npm install`, **Start Command**: `npm start`.
3. В Render → Environment установить `BASE_URL=https://<ваш-сервис>.onrender.com`, длинный `SESSION_SECRET`, `ADMIN_USERNAME=xtc`, **новый** `ADMIN_PASSWORD`. Для SteamID-админов необязательно `ADMIN_STEAM_IDS`.
4. Для постоянной SQLite-базы подключить persistent disk и задать `DB_PATH=/var/data/droplab.sqlite`. Пример `render.yaml` использует платный Render Starter с диском. На бесплатном Render SQLite **может исчезнуть** после повторного развёртывания или перезапуска без постоянного диска. Для надёжной бесплатной инфраструктуры лучше перейти на внешнюю управляемую БД — в этом архиве она **не реализована**.

ZIP — **серверное Node.js-приложение**, поэтому просто загрузить ZIP на статический хостинг Netlify недостаточно.

## Обновление с DROPLAB 4.0

1. Сделать резервную копию SQLite (для активной SQLite WAL-базы нужен согласованный бэкап; проще остановить сервер и скопировать всю базу с `-wal`/`-shm`).
2. Заменить файлы проекта (не заменяя собственную базу данных), установить `ADMIN_PASSWORD` в секретах сервера.
3. Перезапустить `npm start`. Скрипт автоматически добавляет новые таблицы и поля, сохраняя прежние аккаунты, CR, монеты и инвентарь.
4. Текущие гостевые аккаунты сохраняются. Вход по старой сессии остаётся возможен. Для новых гостей включается ограничение по IP и защищённая cookie восстановления.

Рекомендуется после обновления проверить отображение личного профиля и наличие нужной базы через `DB_PATH` перед тем, как открывать сайт другим игрокам.

## Проверка

`npm run check && npm test` проверяют синтаксис и серверные сценарии: стандартный админ, уникальные ID, гостевой лимит, восстановление, email-регистрацию, поддержку, личные шансы, пачку ×9, инвентарь, экономику, контракты. Полная визуальная/кроссбраузерная проверка на всех устройствах не гарантируется.
